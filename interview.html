02. The Science (Model & Evaluation)

The Ensemble AND-Gate (Precision Focus)

LLMs hallucinate (misinterpret) legal text constantly. If you rely on one model, you get a massive amount of False Positives.

  • The Logic: Run a Primary model and Corroborator model simultaneously.
  • The Null Hypothesis: The company is innocent.
  • The VETO: If Model A says "UNSAFE" but Model B says "SAFE", Model B vetoes. The system defaults to SAFE.
  • The "Why": We intentionally sacrifice a tiny bit of Recall to guarantee 94% Precision. We must never falsely accuse an innocent company.

The Confusion Matrix

How the system deals with real-world predictions vs reality.

  • True Positive Catching a company explicitly saying "We sell your data".
  • False Positive (The Hallucination) Accusing an innocent company. Crushed by the Ensemble AND-Gate.
  • True Negative Accurately validating an innocent company's policy.
  • False Negative (The Missed Threat) Missing a complex violation. Fixed via NLP Chunking and Targeted Co-Scanning.

03. The Engineering (Fault Tolerance)

High-Concurrency Fault Tolerance (The Circuit Breaker)

Free tier APIs have a 15 RPM limit per IP. A naive "waterfall" loop hammers the first key, fails, and gives every user a massive hidden latency penalty.

1. Load Balancing: Requests distribute evenly (Key 1 → Key 2 → Key 3). Keys stay cool.
2. Instant Tripwire: If Key 2 hits a 429 Rate Limit, it is marked DEAD and put in a 60-second time-out.
3. Latency Protection: The next user skips Key 2 entirely. Zero failover delay.
4. Fail Fast: If all keys trip, throw a 503 error instantly instead of hanging the user's browser.

Semantic Chunking ("Lost in the Middle")

Even with massive 1M+ token context windows, LLMs suffer from "Lost in the Middle" syndrome on huge documents. We use the compromise NLP library to chunk 25,000-word policies into sentence-aware blocks, forcing the LLM to give 100% attention to every paragraph.

L2 Caching (Bypassing the LLM)

If User A scans Netflix today, the JSON result is saved in Firestore. If User B scans Netflix tomorrow, the backend returns the cached result in 50ms. We completely bypass the LLM, the API limits, and the UI extraction chaos.

04. Frontend Data Extraction (The Wild West)

DOM Settlement (The SPA Problem)

Modern React/Next.js apps use "Skeleton Loaders" while fetching data. If you scrape on page load, you extract zero words. Solution: The extension forces a "DOM Settlement" period, waiting for the skeleton window to disappear and the actual text to render before extracting.

Mozilla Readability Filter

Scraping raw `document.body` results in extracting 3,000 words of garbage (cookie banners, sidebars, nav menus). Solution: We use the @mozilla/readability algorithm to mathematically analyze the DOM tree and strip away structural noise, leaving only pristine article text.

The "Co-Scan" (Fixing False Negatives)

Companies do not put "Data Selling" clauses in their Terms of Service (ToS); they hide them in the Privacy Policy. If we only scan the ToS, we get massive False Negatives.

Solution: When scanning a ToS, the extension silently scans the DOM for a hyperlink to the Privacy Policy. It automatically fetches the HTML of the Privacy Policy in the background, stitches the two documents together, and sends a single combined payload to the backend. The Ensemble Model evaluates BOTH documents simultaneously.
